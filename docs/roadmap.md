# 实施顺序与验收

当前已完成仓库创建和初始设计，以下实现均未完成。主屏视觉方案尚待交互评审，注册和通信边界先行。

## 第一阶段：可独立构建的基础 API

- 建立 Java 17 构建、框架 JAR 产物和最小 Fabric 演示宿主。
- 实现模块身份、版本检查、依赖校验以及原子注册。
- 确定功能、窗口、HUD、槽位栏、主题和背景的最小类型化接口。
- 建立职责明确的状态订阅、动作出口、窗口生命周期和逻辑视口约束。

验收：框架仅使用已声明的构建依赖即可独立构建；演示子 JAR 通过公开 API 注册，缺失依赖、重复 ID 和不兼容版本返回可定位错误。测试保护模块隔离与生命周期契约，不绑定私有字段或源码拼写。

## 第二阶段：主屏与动态注册演示

- 实现功能目录及窗口栏，单例、按对象分实例、最小化和聚焦行为明确。
- 接入两个演示窗口、两种不同数量的槽位栏、共享状态的 HUD。
- 注册默认主题和背景，验证主题切换、资源重载与回退。
- 交付实际运行截图与交互预览，完成布局评审后再深化视觉实现。

验收：新增演示功能、HUD 或背景仅修改演示模块；框架无需新增业务枚举。工作台关闭后 HUD 正常显示，分辨率或 GUI scale 改变时输入命中与绘制一致。

## 第三阶段：通信与库存契约

- 冻结首版模块协商、消息、请求结果和错误协议。
- 通过可控的模拟传输验证完整快照、增量、拒绝、超时和旧连接消息。
- 实现通用库存显示模型、拖放、旋转、分堆及槽位绑定意图。

验收：一个共享库存状态驱动主屏和 HUD；服务端拒绝或超时不造成物品丢失；增量缺口触发重新同步；模块不存在时不会静默吞消息。模拟传输测试与真实网络集成结果分别记录。

## 第四阶段：第三方接入示例与集成验证

- 建立独立示例模组，以版本化依赖使用框架 JAR，演示公开 API 的完整接入过程。
- 提供最小服务端测试端点及宿主网络适配器，验证消息收发与模块能力协商。
- 通过扩展子 JAR 注册库存、物品详情、制作窗口和 HUD，共享库存状态并使用各自命名空间的资源。
- 编写接入指南，说明初始化、模块注册、数据适配、操作结果、资源打包和断线清理。

验收：示例仅依赖公开 API 与声明的产物，Java 17 客户端门禁通过；真实网络往返覆盖移动、分堆、拒绝、断线重连及模块能力；视觉评审通过。引入第三方源码或资源时核对许可证和来源，保留必要声明。

## 第五阶段：首版发布

- 发布可供消费者引用的版本化 Maven 产物和 Fabric 运行 JAR。
- 写明 Minecraft、Fabric、owo、框架 API 和模块协议的兼容范围。
- 提供子 JAR 接入示例、版本升级说明及公开 API 的兼容策略。

验收：干净环境可独立构建；示例子 JAR 只依赖已发布 API；第三方项目可固定版本消费；新增业务窗口、HUD、主题无需修改框架源码。
